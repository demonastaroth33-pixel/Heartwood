# LIFE TREE TRAIT SPACE — the morphological dictionary (DESIGN-SESSION DRAFT)

> **Status:** draft skeleton — the container for the appearance system.
> Filled during the schema session. Authority: the botanical master's
> identification system (Parts 4–10) + VISION principles 7, 8, 17.

## 1. What this document is

The TRAIT SPACE answers ONE question: **what can the tree look like,
and what data decides it?** It holds every visual trait dimension, the
candidate values (the FULL researched variety — all 25 inflorescences,
all 30 fruit types, all 46 organ modifications), the data driver for
each selection, and the coherence rules that keep composites beautiful.

## 2. Trait dimensions (each = data-driven selection)

- Crown / branching type (monopodial, sympodial, excurrent,
  decurrent…) — driver: dominant domains, focus balance
- Bark type (smooth, fissured, papery, corky…) — driver: age + years
  of consistency
- Leaf family (shape, margin, venation, phyllotaxy, compound-ness) —
  driver: per-section character (journal = ?, gym = ?, habits = ?)
- Flower / inflorescence family (the full 25) — driver: achievement
  families + tiers
- Fruit type (the full 30) — driver: goal completions + milestones
- Ring character (earlywood/latewood width, color, false/missing
  rings) — driver: yearly quality
- Root character (taproot vs spreading, modifications) — driver:
  foundation years, early consistency
- Modifications (the full catalog: caudex, phyllodes, reaction wood,
  succulence…) — driver: long streaks, drought periods, special
  states, super-hard achievements
- Seasonal phase visuals (bloom intensity, canopy density, autumn
  color, dormancy) — driver: calendar + data intensity

## 3. The coherence envelopes (the anti-zombie rule — VISION §6, D088)

- **No single environment.** The tree's character = its POSITION on
  four continuous axes (resource, rhythm, balance, tenure — 0.0–1.0,
  derived from the event log). The lineage character IS the axis
  position.
- **One character per organ:** the trunk, root system, leaf family,
  and branch structure each carry ONE character at a time —
  same-organ contradictions are the hard floor.
- **Axis signatures:** every adaptation (and every trait-family
  selection) declares its required axis ranges; contradictions are
  impossible by construction because all adaptations read the same
  numbers.
- **Overlap is natural** in the middle ranges (the Mediterranean
  position: drought-tolerant + cold-season traits coexist — real
  botany).
- **Rank rule:** strongest data support wins the dominant character
  on an organ; compatible runner-ups render at a subtle tier.
- **Universal adaptations** (no restrictions): reaction wood,
  epicormic shoots, mycorrhizal/coach symbiosis, bracts, contractile
  roots, bud scales.
- **Verification:** seeded-data stress tests + the archetype mockups
  include a botanical-contradiction check (a generated tree must
  pass every adaptation's axis signature or the engine does not
  ship).

## 4. Explainability (the why-panel)

Every visible trait carries its derived explanation: trait → data →
reason. The why-panel is a first-class output of the derivation
(VISION §11).

## 5. Rendering constraints (the perf pillar)

Stylized botanical art (heartwood language), instanced procedural
leaves, LOD, cheap anatomy views — beauty at low-end-device cost
(per the performance agreement; verified by perf budgets as milestone
gates).
## 4. THE LEAF-FAMILY ENVELOPE (LOCKED - D115, the last zombie vector)

The tree derives ONE base leaf character from the axes; per-branch
variation picks SIBLING FORMS WITHIN THAT FAMILY ONLY (margin/shape
variants), never crossing into another family's envelope. The canopy's
most visible scale is bound to the same coherence system as every
other trait.
